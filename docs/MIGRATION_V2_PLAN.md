# 🗺️ Master Plan: Поэтапный переход Travel Monitor 2.0 (База данных + API + React UI)

Этот документ фиксирует архитектурный план полного переноса функционала и логики из v1 (статические HTML-дашборды на базе CSV-архивов) на современный стек v2 (SQLite/PostgreSQL + FastAPI + React SPA) с сохранением 100% точности исторических данных.

---

## 📌 Архитектурный принцип перехода

1. **Никакой генерации статических тяжелых HTML на сервере:**
   - В v1 генератор создавал 20-мегабайтные HTML-страницы с запеченными графиками.
   - В v2 фронтенд — это легкое React SPA, запрашивающее данные по REST API короткими JSON-ответами за <50 мс.
2. **Чистота когорт и отсутствие смешивания данных:**
   - Вся история цен отеля строго изолирована в рамках фильтра (`filter_id`, состав семьи `adults`/`children`, даты вылета и длительность).
   - Исключено объединение цен на 1 человека и на семью 2+1.
3. **Хранение всей истории (2.3M+ строк) в реляционной БД:**
   - Все 237 еженедельных архивов `data/filters/*/archive/travel_prices_*.csv` переносятся в базу данных со сквозными индексами по времени и когортам.

---

## 🚀 Декомпозиция этапов реализации

### Этап 1. База данных и полный импорт архивов CSV (2.3+ млн строк)
* **Цель:** Перенести всю непрерывную историю с 01.06.2026 по текущий момент в базу данных v2.
* **Задачи:**
  1. Разработать пакетный скрипт миграции `scripts/import_full_v1_archives.py`:
     - Сканирование всех 23 папок фильтров `data/filters/*/`.
     - Сквозное чтение 237 архивов `archive/travel_prices_YYYY-wWW.csv` + текущих `travel_prices.csv`.
     - Генерация уникальных детерминированных `cohort_hash` с фиксацией параметров (`filter_id`, `adults`, `children`, `checkin_date`, `duration_nights`, `airport_code`).
     - Пакетная вставка (`executemany` по 50 000 строк) в таблицы `hotels`, `offer_cohorts`, `price_snapshots`.
  2. Добавление составных индексов в БД:
     - `idx_snapshots_cohort_time ON price_snapshots(cohort_hash, recorded_at)`
     - `idx_cohorts_filter ON offer_cohorts(destination_code, hotel_id)`
* **Критерий завершения:** В базе данных `travel_monitor_v2.db` присутствует непрерывная история с 01.06.2026 (>2.3M строк). Запрос истории любого отеля (например, IL Mercato) возвращает полный диапазон дат без пропусков.

---

### Этап 2. График «Средняя цена ТОП-10 дешёвых предложений»
* **Цель:** Воссоздать динамический график ТОП-10 на базе API с идентичной v1 математикой.
* **Задачи:**
  1. Реализовать эндпоинт `GET /api/filters/{filter_id}/top10-timeline`:
     - Параметры: `range=all|30d|7d`, `ceiling_pln` (по умолчанию 10 000 PLN).
     - Почасовая группировка: на каждый час вычисляется минимальная цена каждого отеля в рамках фильтра.
     - Оконная функция: отбор ТОП-10 самых дешевых отелей за этот час.
     - Агрегация: расчет средней цены (`avg_price`), минимума (`min_price`), максимума (`max_price`) и коридора колебаний (IQR / доверительный интервал).
  2. Фронтенд-компонент:
     - Отрисовка интерактивного графика (Recharts / Chart.js) с заливкой коридора мин-макс цен и линией тренда.
* **Критерий завершения:** График ТОП-10 для любого фильтра строится плавной кривой без провалов (как на скриншоте 3).

---

### Этап 3. Каталог отелей, Deal Score и бейджи
* **Цель:** Заменить статическую таблицу на динамический каталог отелей.
* **Задачи:**
  1. Реализовать эндпоинт `GET /api/filters/{filter_id}/hotels`:
     - Возвращает отели с текущей минимальной ценой, динамикой за 24ч (-%) и 7д (-%), рейтингом TripAdvisor, фото и бейджами (`Исторический минимум`, `Снижение цены`).
     - Расчет `Deal Score` (индекс выгоды на основе истории).
     - Поддержка параметров сортировки: по цене, по скидке, по TripAdvisor, по Deal Score.
  2. Фронтенд-компоненты:
     - Табличный вид (`HotelTable`) и карточный вид (`HotelGrid`) с быстрым переключателем.
     - Быстрый поиск по названию отеля и фильтрация по звездам (4★, 5★).
* **Критерий завершения:** Каталог мгновенно реагирует на поиск, фильтрацию и сортировку, отображая те же карточки, что и в v1.

---

### Этап 4. Дровер отеля (Modal Drawer) — 4 вкладки
* **Цель:** Интерактивное модальное окно деталей отеля с чистой историей цен.
* **Задачи:**
  1. Реализовать эндпоинты:
     - `GET /api/hotels/{hotel_id}?filter_id={filter_id}`: основная информация, бейджи инфраструктуры, ссылки на YouTube и TripAdvisor.
     - `GET /api/hotels/{hotel_id}/history?filter_id={filter_id}&range=all|30d|7d`: непрерывная история цен отеля **строго в контексте выбранного фильтра**.
     - `GET /api/hotels/{hotel_id}/departures?filter_id={filter_id}`: матрица всех доступных дат и аэропортов (WAW, WMI, RDO).
  2. Фронтенд-компонент `HotelDrawer`:
     - **Вкладка 1 (AI-Обзор и отзывы):** резюме, плюсы/минусы, переход на YouTube / TripAdvisor.
     - **Вкладка 2 (Анализ и график цен):** гладкий график без «пилы» (устранено смешивание 1p и 2+1), метрики (текущая, минимум, максимум, экономия от пика, статус стабильности).
     - **Вкладка 3 (Инфраструктура):** бейджи (бассейны, пляж, аквапарк).
     - **Вкладка 4 (Все вылеты):** список вылетов с ценами.
* **Критерий завершения:** График IL Mercato и других отелей отображает гладкую кривую с июня по ноябрь (как на скриншоте 4) без скачков между 4k и 11k.

---

### Этап 5. Сайдбар фильтров и AI Market Oracle
* **Цель:** Навигация между всеми 23 направлениями и вывод аналитического прогноза.
* **Задачи:**
  1. Реализовать эндпоинт `GET /api/filters`:
     - Группировка по странам: Турция, Египет, Греция, Кипр, Раннее бронирование, Архив.
     - Счетчик актуальных отелей для каждого фильтра.
  2. Реализовать эндпоинт `GET /api/filters/{filter_id}/oracle`:
     - Прогноз динамики цен перед вылетом (`Ближайшие вылеты через X дн...`).
  3. Фронтенд-сайдбар:
     - Client-side роутинг (`/filters/:filterId`) без перезагрузки всей страницы в браузере.
* **Критерий завершения:** Переключение между Турцией, Египтом и архивами происходит за миллисекунды в едином SPA.

## 🔄 Автоматизация и CI
* Ежечасный скрапинг Fly.pl запускается по крону в GitHub Actions (`monitoring.yml`).
* Данные парсятся и записываются в базу данных, после чего база синхронизируется.
* Веб-сервер на Railway отдает API и статический билд фронтенда.
